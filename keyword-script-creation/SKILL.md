# 关键词脚本生成

把「剧本 + 分镜」变成「AI 能照着生成的序列组」。**先对齐、再算账、后写字，账目不平不交付。**

## 0. 这个技能解决什么

| 不做 | 要做 |
|---|---|
| 拿起分镜就开始写提示词 | 先读剧本＋分镜，逐句逐镜对齐 |
| 写完才发现时长对不上 | 先出总览表算账（组数/时长/台词秒） |
| 用「愤怒地/悲伤地」糊过去 | 情绪走肌肉参数，动作走七要素，带呼吸 |
| 引用只写「参考《无间道》」 | 附件6 原文内联＋本组取用 |
| 每组重新想人物长什么样 | 人物/场景/空间锚点逐组复写 |
| 交付一堆散装文字 | 一个 Excel（5 sheet）＋ 源 JSON ＋ 自检记录 |

## 1. 输入契约

**必填（缺就问，别猜）**：① 剧本文档（docx/txt）② 分镜头脚本文档（xlsx/docx）③ 集数/片名 ④ 交付目录。
**可推断**：模式（看画幅与总时长）、编号前缀、模型。
**选填**：上一集成品（接续用）、项目 `_生成设定.md`（优先级高）、参考图、台词烈度。

- 画幅/模式无法判断 → 一次问清，不要默认。
- 分镜与剧本对不上 → 先出「对齐报告」，让用户裁决，不自行改剧情。
- 有 `_生成设定.md` 先读它，项目设定优先于技能默认。

## 2. 模式判定

| 模式 | 判定线索 | 编号 | 单组 | 全片 |
|---|---|---|---|---|
| `vertical` 竖屏短剧 | 9:16 / 1080×1920 / 单集短剧 | `SXX-XZ-001` | 4–15s，禁 2.5 | 单集 ≤3 分钟 |
| `horizontal` 横屏短剧 | 4:3 / 1920×1440 / 单集短剧 | `SXX-XZ-001` | 4–15s，2.5≤30s | 单集 ≤3 分钟 |
| `shortfilm` 横屏短篇 | 4:3 / 总时长 10–15 分钟 / 说「短片、微电影」 | `M1-C03-XZ-012` | 4–15s，2.5≤30s | **600–900 秒** |

画幅永远来自用户或分镜文档，上表只描述典型值，不得当默认。

## 3. 九步工作流（短篇多一步规划）

### 第 0 步 · 参数与设定
读 `_生成设定.md`（若有），确认画幅、集数、模式、交付目录、是否接续上一集。

### 第 1 步 · 规范研读（按顺序加载）
1. `references/05-裁决-落地要求.md` ← **最高优先级，必读**
2. `references/00-总纲-红线与字段.md`
3. 模式文件：`10-模式-竖屏9x16.md` / `20-模式-横屏4x3.md` / `30-模式-横屏短篇10-15min.md`
4. 写到哪读到哪：`40` 画面参数 → `45` 技法到参数 → `50` 提示词 → `51` 妆造风格 → `60` 分镜 → `70` 音频 → `80` 反向
5. 交付前读 `90-自检清单与报告.md`
6. 要取库条目时看 `95-库索引.md`，用 `lib/refs.py` 取，不整库读

### 第 2 步 · 输入对齐
```bash
python scripts/ingest.py --script <剧本.docx> --storyboard <分镜.xlsx> --out work/<片名>_S03_source.json
```
产出：规范化原文清单、分镜行、单元汇总、锚点、**对齐报告**（剧本有而分镜无 / 分镜有而剧本无 / 单元超限 / 跨场景 / 无单元列）。
★ **停车点**：缺口未裁决，不进入切组。

### 第 3 步 · 序列组规划与账目
- 切组（同场景＋4–15 秒＋一个核心事件），分配模型，编号，算台词秒数；
- 短篇：先出三幕/场次/八节点/总览表，再切组；
- 产出 `总览表`：组号｜场景｜时长｜模型｜核心事件｜台词秒｜累计。
★ **闸门 1**：总览表确认后才写正文（短篇此处拆成「结构闸门」＋「总览闸门」两道）。

### 第 4 步 · 样张
写 1–2 组（一个对白组＋一个高潮/动作组），交用户看颗粒度。
★ **闸门 2**：风格、信息密度、物理化程度确认后才批量。

### 第 5 步 · 分批写作
每批 1 场或 5–8 组；写进 `kwdata.json`（单一数据源），**禁止**在别处另写一份。
每组十字段全部落 JSON，人物/场景/空间锚点逐组复写。

### 第 6 步 · 三次循环自检
边写边查；全部写完后按 `90` 的表 1→2→3 逐条过，填问题与修改措施。

### 第 7 步 · 机器校验
```bash
python scripts/verify.py work/<片名>_S03_kwdata.json --strict
```
error 清零；warning 逐条说明。修完重跑，直到干净。
技能自身改过脚本后，跑 `python tests/run_all.py` 回归（四库 280 条、竖屏样例、短篇夹具、覆盖检查、真实分镜 ingest）。

### 第 8 步 · 生成交付件
```bash
python scripts/build_xlsx.py work/<片名>_S03_kwdata.json --out "out/<片名>_S03_关键词_v1.xlsx"
```
生成 4 个 sheet（短篇 5 个，多一张全片总览）；打开检查行高/换行/无截断。

### 第 9 步 · 交付
Excel ＋ 同名 `_kwdata.json` ＋ 自检报告 ＋ 待确认项 ＋ 版本行。
默认路径：`关键词脚本\{剧名}\{剧名}_S{集}_关键词_v{n}.xlsx`。

## 4. 输出契约

| Sheet | 内容 |
|---|---|
| `关键词脚本` | 10 列，一行一组，与规范字段同名同序 |
| `全片序列组总览` | 短篇必出：幕/场/编号/场景/时长/模型/核心事件/累计 |
| `三次循环自检` | 三张清单＋报告汇总，含问题与修改措施 |
| `梗概与锚点` | 故事、钩子/反转、人物/道具/视觉/空间锚点、时长账目、引用索引、版本 |
| `台词时长账目` | 每组台词字数、语音秒、留白、合计、差值 |
| `技法映射` | 按需生成：组号/镜号/技法/落点/档位/参数片段（`shot.tech` 有值才出） |

**命名**：`{剧名}_S{集}_关键词_v{n}.xlsx`；源数据 `{剧名}_S{集}_kwdata.json` 同目录。
**版本行**：`V1.0｜2026-10-26｜依据竖屏V2.5｜cine_tech v1.0｜修改人：…`

## 5. 硬规则速查（违反即返工）

1. 十字段齐全、顺序固定、每组自包含，禁「同上/同前/同左」。
2. 组时长 4–15 秒，**必须是整数秒**（写 7 秒，不写 7.2 秒）；竖屏禁 2.5；横屏 2.5 ≤30 秒并标【2.5模型】；同组模型唯一。
3. 同组不跨场景；全硬切；无 BGM；文字后期叠加。
4. 时间轴 0.0 起、首尾相接、末段=组时长、0.1 秒精度。
5. 每段七字段齐全，含微表情、呼吸、镜头物理参数。
6. 动作七要素；情绪肌肉参数；禁抽象情绪词。
7. 台词逐字；语速 2.25 字/秒（2.0–2.5）；台词量 5–12 秒；留白 ≥0.5 秒。
8. 反向五段，画幅项按模式写死，剧情不符项逐组改写。
9. 附件6 全内联；附件3/4/5 条名＋参数；只写条号=不合格。
10. 站位用物理方位＋相对关系，禁裸「居左/居右」；位置/朝向/视线/手别/机位五者自洽。
11. 有台词的角色必须出镜；群像拆多分镜，不堆一个镜头。
12. 三次自检＋`verify.py` 双通过才交付。
13. 一条技法只落一处（45 §1）；**英文技法名不得进正向提示词**，必须降维成参数（45 §2）。
14. 一镜一主运镜：单镜只 1 个运动轴，辅技法 ≤2 且不同轴；T4 禁投只用替代写法（45 §5）。
15. 参考电影 ≤1 部写《片名》年份；典故不得出现在 pic/style（CT05/CT06）。

## 6. 高频翻车点

| 翻车 | 症状 | 纠正 |
|---|---|---|
| 拿分镜当剧本 | 分镜漏了台词，脚本也漏 | 回剧本逐句核，ingest 对齐报告 |
| 账目对不上 | 各组时长之和 ≠ 总时长 | 重算切组，不改数字凑 |
| 提示词断秒 | 末段 11.8 秒但组时长 12.3 | 补 0.5 秒留白段或修时间轴 |
| 情绪贴标签 | 写「她很愤怒」 | 换肌肉参数＋呼吸 |
| 引用裸条号 | 「附件6 电视剧第11条」 | `refs.py expand` 重写 |
| 竖屏用 2.5 | 20 秒一组 | 拆组 |
| 群像堆一镜 | 五个人挤在画面里 | 拆分镜＋拆反应镜 |
| 空镜凑时长 | 无信息画面 | 换细节镜/道具镜 |
| 台词超时 | 15 字塞进 4 秒 | 拆组或压缩口语化（留痕） |
| 只有声音没画面 | 有台词但人在画外 | 补出镜镜或标电话/主观 |

## 8. 典型调用

**例 1**：用户发来剧本＋分镜＋「按关键词技能做《X》第 3 集」
→ 读设定 → ingest 对齐 → 切组账目 → 总览表确认 → 样张 → 批量 → 自检 → 校验 → 交付。

**例 2**：用户只给分镜
→ 停，要剧本；说明「关键词脚本必须逐字还原台词，缺剧本会改剧情」。

**例 3**：用户说「继续第 4 集」
→ 读第 3 集 kwdata 与自检，接续空间/人物/编号，不重写已确认内容。

**例 4**：用户说「太慢了，直接全出」
→ 可以一次出多组，但仍必须先给总览表；账目对了再写，否则返工更慢。

**例 5**：用户要改某一句台词
→ 改 `kwdata.json` 里对应 shot，重跑 build；**不许直接改 Excel**。
