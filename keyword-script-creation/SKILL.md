# 关键词脚本生成

**版本行**：`V2.12｜2026-11-26｜第 0 段固定禁用 ＋ [图片N] 素材上限 ＋ 分镜图按档位 ＋ 多镜组与图锚 ＋ 提示词字数预算／数据契约；CT16–CT33`

- 改稿前先读项目同目录的 `<剧名>_S<集>_生成设定.md`（优先级高）、参考图、台词烈度。

- 画幅/模式无法判断 → 一次问清，不要默认。
- 分镜与剧本对不上 → 先出「对齐报告」，让用户裁决，不自行改剧情。
- 有 `_生成设定.md` 先读它，项目设定优先于技能默认。

## 2. 模式判定

| 模式 | 判定线索 | 编号 | 单组 | 全片 |
|---|---|---|---|---|
| `vertical` 竖屏短剧 | 9:16 / 1080×1920 / 单集短剧 | `SXX-XZ-001` | 4–15s，禁 2.5 | 单集 ≤3 分钟 |
| `horizontal` 横屏短剧 | 4:3 / 1920×1440 / 单集短剧 | `SXX-XZ-001` | 4–15s，2.5≤30s | 单集 ≤3 分钟 |
| `shortfilm` 横屏短篇 | 4:3 / 总时长 10–15 分钟 / 说「短片、微电影」 | `M1-C03-XZ-012` | 4–15s，2.5≤30s | **600–900 秒** |

画幅永远来自用户或分镜文档，上表只描述典型值，不得当默认。

## 3. 九步工作流（短篇多一步规划）

### 第 0 步 · 参数与设定
读 `_生成设定.md`（若有），确认画幅、集数、模式、交付目录、是否接续上一集。

### 第 1 步 · 规范研读（按顺序加载）
1. `references/05-裁决-落地要求.md` ← **最高优先级，必读**
2. `references/00-总纲-红线与字段.md`
3. 模式文件：`10-模式-竖屏9x16.md` / `20-模式-横屏4x3.md` / `30-模式-横屏短篇10-15min.md`
4. 写到哪读到哪：`40` 画面参数 → `41` 运镜库／`42` 打光库（要落具体镜头语言与光位时）→ `45` 技法到参数 → `48` 开场钩子（写每组前 2 秒时必读）→ `49` 节奏与可读性（排整集快慢、查台词余量时）→ `50` 提示词 → `51` 妆造风格 → `52` 表演三拍（写动作连续性时）→ `55` 类型成品提示词（找同类写法／对颗粒度时）→ `60` 分镜 → `70` 音频 → `80` 反向
5. 交付前读 `90-自检清单与报告.md`
6. 要取库条目时看 `95-库索引.md`，用 `lib/refs.py` 取，不整库读；六个写法库（41/42/48/49/52/55）是整篇读的，见 `95` 第九节
7. **打戏必读** `references/56-武打物理参数与音效对齐.md`（1/4–1/5 倍速、受力四段、打击音与命中帧同帧）；分镜层的拍法与逻辑见 `storyboard-creation/references/53-武打动作组.md`

### 第 2 步 · 输入对齐
```bash
python scripts/ingest.py --script <剧本.docx> --storyboard <分镜.xlsx> --out work/<片名>_S03_source.json
```
产出：规范化原文清单、分镜行、单元汇总、锚点、**对齐报告**（剧本有而分镜无 / 分镜有而剧本无 / 单元超限 / 跨场景 / 无单元列）。
★ **停车点**：缺口未裁决，不进入切组。

### 第 3 步 · 序列组规划与账目
- 切组（同场景＋4–15 秒＋一个核心事件），分配模型，编号，算台词秒数；
- 短篇：先出三幕/场次/八节点/总览表，再切组；
- 产出 `总览表`：组号｜场景｜时长｜模型｜核心事件｜台词秒｜累计。
★ **闸门 1**：总览表确认后才写正文（短篇此处拆成「结构闸门」＋「总览闸门」两道）。

### 第 4 步 · 样张
写 1–2 组（一个对白组＋一个高潮/动作组），交用户看颗粒度。
★ **闸门 2**：风格、信息密度、物理化程度确认后才批量。

### 第 5 步 · 分批写作
每批 1 场或 5–8 组；写进 `kwdata.json`（单一数据源），**禁止**在别处另写一份。
每组十字段全部落 JSON，人物/场景/空间锚点逐组复写。
人物锚点**不要现编**：从上一环节的 `角色锚点.json`（`stage=full` 的角色才有 anchor 与 features）整段抄，`stage=names` 的说明那角色还没定貌——先去定貌，别在关键词里临时给长相。规范见 `drama-pipeline-gate/references/角色锚点两阶段_v1.md`。

### 第 6 步 · 三次循环自检
边写边查；全部写完后按 `90` 的表 1→2→3 逐条过，填问题与修改措施。

### 第 7 步 · 机器校验
```bash
python scripts/verify.py work/<片名>_S03_kwdata.json --strict
```
error 清零；warning 逐条说明。修完重跑，直到干净。
手上已有这集的**分镜 JSON**（分镜技能的 ingest 产物，或分镜表 units）时，再跑一次跨表校验——两边镜数、秒数、景别、台词对不上就在这里现形：
```bash
python scripts/crosscheck.py --storyboard <分镜 JSON> --keyword work/<片名>_S03_kwdata.json
```
镜号按位置比（关键词镜号每组从 001 重数），X02/X03 是硬错（漏镜/多镜），X04–X07 是账目警告。
技能自身改过脚本后，跑 `python tests/run_all.py` 回归（四库 280 条、竖屏样例、短篇夹具、覆盖检查、跨表正负例、真实分镜 ingest）。

### 第 8 步 · 生成交付件
```bash
python scripts/build_xlsx.py "<项目根>/<片名>_S03_kwdata.json" --out "<项目根>/<片名>_S03_关键词_v1.xlsx"
```
生成 4 个 sheet（短篇 5 个，多一张全片总览）；打开检查行高/换行/无截断。

### 第 9 步 · 交付
Excel ＋ 同名 `_kwdata.json` ＋ 自检报告 ＋ 待确认项 ＋ 版本行。
默认路径：`关键词脚本\{剧名}\{剧名}_S{集}_关键词_v{n}.xlsx`。

## 5. 硬规则速查（违反即返工）

1. 十字段齐全、顺序固定、每组自包含，禁「同上/同前/同左」。
2. 组时长 4–15 秒，**必须是整数秒**（写 7 秒，不写 7.2 秒）；竖屏禁 2.5；横屏 2.5 ≤30 秒并标【2.5模型】；同组模型唯一。
3. 同组不跨场景；全硬切；无 BGM；文字后期叠加。
4. 时间轴 0.0 起、首尾相接、末段=组时长、0.1 秒精度。
5. 每段七字段齐全，含微表情、呼吸、镜头物理参数。
6. 动作七要素；情绪肌肉参数；禁抽象情绪词。
7. 台词逐字；语速 2.25 字/秒（2.0–2.5）；台词量 5–12 秒；留白 ≥0.5 秒。
8. 反向五段，画幅项按模式写死，剧情不符项逐组改写。
9. 附件6 全内联；附件3/4/5 条名＋参数；只写条号=不合格。
10. 站位用物理方位＋相对关系，禁裸「居左/居右」；位置/朝向/视线/手别/机位五者自洽。
11. 有台词的角色必须出镜；群像拆多分镜，不堆一个镜头。
12. 三次自检＋`verify.py` 双通过才交付。
13. 一条技法只落一处（45 §1）；**英文技法名不得进正向提示词**，必须降维成参数（45 §2）。
14. 一镜一主运镜：单镜只 1 个运动轴，辅技法 ≤2 且不同轴；T4 禁投只用替代写法（45 §5）。
15. 参考电影 1 部主对标 + 至多 2 部辅对标（辅须标「（辅）」，只供节奏/调度，不参与风格合成）；主对标写《片名》年份；技法库条目引用（附件 N…第 M 条【技法名】）同样合法；典故不得出现在 pic/style（CT05/CT06）。
16. 每组前 2 秒必须有钩子（`48`）：钩子写进七字段正文，**不写进 movement、不写进反向提示词**；一组 ≤3 条且分属不同通道（视觉/听觉/空间）。
17. 运镜与光影只从 `41`/`42` 的取值域里挑：运镜四要素（方向＋幅度＋速度＋时长），光影四件套（光位＋光质＋色温＋光比）；英文名只能当检索别名，进正向即 CT07。**CT09** 查运镜有没有轴与量化、**CT10** 查光影有没有色温 K 与光比、**CT11** 查钩子有没有跑进运镜、**CT12** 查英制单位——这几条 `verify.py` 会拦，别等交付。
18. 整集要有速度曲线（`49`）：一处明确加速、一处明确减速、一个「呼吸」组；不许连续 3 组 <5 秒，也不许整集组时长一个样。台词说完到组末留 ≥0.6 秒，关键动作留够看得懂的尾帧。**CT13/CT15** 会拦。
19. 动作写三拍（`52`）：预备—动作—跟随；一段只放一个完整动作组；重心、支撑脚、手与道具的接触点都要写出来。一集运动轴 ≥4 种并留一个招牌镜（**CT14**）。
20. **反向提示词必须有第 0 段**（V2.0，`80`）：`视频全程禁止出现任何字幕，禁止文字叠加，必须是纯画面；禁止出现任何bgm，禁止配乐。` 逐字照抄，每组都在，不参与动态改写。缺字幕禁令或缺 BGM 禁令即 error（CT21）。
21. **`[图片N]` 先算预算再编号**（V2.0，`40` §四·五）：2.0 系列 9 图/3 视频/3 音频（音频不可单独用，须配 ≥1 图或视频，本组生成 **4–15 秒**、单条参考 4–15 秒，视频组与音频组各 ≤15 秒）；2.5 flash 10/5/5（本组生成 **4–30 秒**、单条参考视频/音频 **4–30 秒**，组总时长各 ≤30 秒）；2.5 标准版 30/10/10（本组生成 **4–30 秒**、单条参考 **4–30 秒**，支持纯音频参考，组总时长各 ≤30 秒）。**三档的组时长下限一律 4 秒**——没有哪个档位能生成 2–3 秒的组。**档位不统一**（V2.2）：默认 2.0，逐组按情节与场景决定要不要升 2.5，同组模型唯一。**该升 2.5 的四种情形**：① 同一组要引超过 9 张图（多人同框＋道具＋场景）② 需要纯音频驱动口型/节奏 ③ 单组要 15–30 秒的长调度（长镜、跟拍、连续动作）④ 高密度打戏或多人交叉调度。**不该升的**：常规 4–15 秒对话与单人近景、竖屏短剧（竖屏禁 2.5）、预算紧的抽卡阶段（先用 2.0 试构图，定了再升）。超预算说明该拆组（CT17）。
22. **正文 `[图片N]` 与 refs 双向对齐**（V2.0）：每个编号都要在 `refs` 里有 `{n, kind, file, role}`，每个 refs 条目都要在正文被引用；图片必须给 `file`（CT17）。
23. **身份链禁止代际传递**（V2.0，CT23）：长相／发型／服装只引**原始大脸卡**，不许"上一段生成图 → 当下一段的脸参考"；空间锚点（站位／墙／家具）可以逐段传，但必须同时挂 `scene_ref` 原始无人场景图。链深 > 1 即 error。
24. **色卡先于分镜图**（V2.0，CT18）：每组写 `彩色基准COLOR-{集号}-{字母}`，色温与色卡偏差 ≤800K；引用不存在的色卡即 error。正文里写的每个 #RRGGBB 都必须能在所引色卡里找到（现编一个就会报 error），色卡的每个色必须带 rom 注明取自场景图哪一处，主色 3–5 个。
25. **写实风格要分前中后景**（V2.0，CT20）：每组 `layers`（fore/mid/back）至少填一层；连续 3 组三帐全空判 warning——那是"人物贴在一块板子上"的典型症状。
26. **武打组要补受力与重心**（V2.0，CT19）：动作六阶段里"受力反馈"和"重心恢复"必须写出来；升格只用于一个关键动作，出现 ≥2 次判 warning。
27. **背景人物要有自己的事**（V2.0，CT24）：群像／公共场景写 `bg_basis`，指向本项目场景图（不能只给编号）；背景人物写独立不同步的行为，不做齐步走的背景板。
28. **短镜落地写 `landing`（V2.3）**：`shots[].landing` ＝ `并进`（默认）／`后期`／`砍掉`；标了砍掉仍留在组里、或 ≥4 秒的镜头标后期/砍掉，CT26 报 warning。
29. **分镜图引用按档位（V2.4）**：`refs` 里分镜图标 `kind: board`——2.0 系列写 `role: first_frame`（它是整组生成起点，**不当单镜画面参考**）；2.5 flash / 2.5 标准版写 `role: shot_ref`（逐镜画面参考）。分镜图**也占一张图片名额**（9/10/30 里要扣掉它，V2.12 平台实测），且不参与身份链（CT17/CT23）；2.5 里它可以**兼首帧**（同一张既是 shot_ref 又是生成起点）。
30. **纯文字路径要显式声明（V2.3）**：一组既没有 `refs` 也没有 `[图片N]` 时，要么补参考图，要么在组头写 `ref_mode: text` 认下这条路——不声明时 CT17 报 warning（长相与场景全靠提示词兜）。
31. **组时长下限一律 4 秒**（V2.3）：2.0 组 4–15 秒、2.5 flash 与 2.5 标准版组 4–30 秒；三档单条参考 video/audio 都是 4 秒起（2.0 到 15 秒，2.5 到 30 秒）。
32. **多镜组一镜一句、单组最多 6 镜、镜里点名**（V2.5）：组内 ≥2 镜时 `prompt` 要自带 `镜N（起-止 秒）：景别，动作；切点＝…`，标记数＝`shots` 数（CT27）；镜里角色写名字，不许写「两人/三人/他们/大家」；末镜写整组收在哪。正文用 `[图锚 KB_S03_U01]` 指名分镜图，必须落在 `refs.file` 里（CT17）。
33. **分镜图只在 >15 秒的组里用**（V2.6）：4–15 秒走 2.0，`refs` 不挂分镜图（挂了 CT17 warning）；15–30 秒的 2.5 组才挂 `kind: board`。分镜图仍照常产出（1/3 抽帧），只是不进 2.0 的参考表。
34. **整集一套风格包**（V2.6）：`data.style_pack` 只能取 `modern_live`／`ancient_period`／`3d_stylized`（认「现代/古装/3D」别名）；不在枚举里 CT28 error，出了分镜图却没写 CT28 warning。单元 `style` 只补差异。
35. **风格前缀只有一份正文**（V2.8）：视频提示词的第 0 段同样照抄 `ct_rules.STYLE_PACKS[pack]["prefix"]`（`style_prefix()` 可取），不要换措辞。
36. **原生配音进资产表**（V2.8）：抽出来的 `AUD_*` 要登记进 `assets.audios[]` 再在 `refs` 里以 `kind: audio` 引用（CT29）；资产根统一 `--assets-root`，`file` 写含子目录的相对路径。
37. **声线照抄锚点**（V2.9）：有台词的角色在 `anchors.characters[].voice` 写 `timbre`/`rate`/`accent`，本组 `sfx_layers.voice` 点名复写；缺一个 CT30 报 warning——平台原生配音按台词自己挑嗓子，不写就换一集换人。
38. **多镜组的分镜图带镜号**（V2.9）：`assets.boards[].shot` 填 `S01`/`S02`，与单元内镜头一一对应（CT25 判缺镜）。
39. **首帧唯一、role 走枚举**（V2.10）：`first_frame` 一组一张且必须是分镜图；资产图 role 用 `look_ref`／`cloth_ref`／`item_ref`／`scene_ref`；>15 秒组没标首帧要提示（CT31）。
41. **提示词字数有预算**（V2.12，平台实测）：**2.0 上限 4000 字、2.5（含 flash）10000 字以内**，软预算取 3/4（3000／7500，都含风格前缀与禁用句）；超了先拆组——被截断时是后半截镜头不生成，不报错（CT32）。
42b. **分镜图占名额、可兼首帧**（V2.12，平台实测）：`kind: board` 的那一张**也占一张图片名额**（2.0 的 9 张里要扣掉它；「九图给满再挂一张关键帧」在 2.0 会被 CT17 判超限）；2.5 里同一张分镜图可以**兼首帧**（`role` 同时写 `shot_ref` 与 `first_frame`），一组仍只能有一张首帧（CT31）。
42. **数据契约三件**（V2.11）：`schema: "kwdata/1"`；`meta` 键名照 `META_KEYS`（笔误会被提示）；资产桶内 id 不许重复（CT33）。
40. **漏台词是 error**（V2.6）：`ingest.py` 发现剧本台词在分镜里找不到会 `exit 1`；确认这些台词真的不要了，才加 `--allow-drop` 重跑。

## 6. 高频翻车点

| 翻车 | 症状 | 纠正 |
|---|---|---|
| 拿分镜当剧本 | 分镜漏了台词，脚本也漏 | 回剧本逐句核，ingest 对齐报告 |
| 账目对不上 | 各组时长之和 ≠ 总时长 | 重算切组，不改数字凑 |
| 提示词断秒 | 末段 11.8 秒但组时长 12.3 | 补 0.5 秒留白段或修时间轴 |
| 情绪贴标签 | 写「她很愤怒」 | 换肌肉参数＋呼吸 |
| 引用裸条号 | 「附件6 电视剧第11条」 | `refs.py expand` 重写 |
| 竖屏用 2.5 | 20 秒一组 | 拆组 |
| 群像堆一镜 | 五个人挤在画面里 | 拆分镜＋拆反应镜 |
| 空镜凑时长 | 无信息画面 | 换细节镜/道具镜 |
| 台词超时 | 15 字塞进 4 秒 | 拆组或压缩口语化（留痕） |
| 只有声音没画面 | 有台词但人在画外 | 补出镜镜或标电话/主观 |
| 开场慢热 | 前 2 秒还在交代环境、镜头扫房间 | 换 `48` 的模板，第一帧就放异常 |
| 钩子假预告 | 开头炸一场，后面接不上 | 钩子必须由本组核心事件当场兑现 |
| 光只写「氛围感」 | 没有光位、色温、光比 | 走 `42` 四件套，光比给数字 |
| 运镜写成名字 | 「缓慢推镜」四个字了事 | 补方向/幅度/速度/时长，查 `41` 总表 |
| 一个速度走到底 | 整集十二组全是 8 秒 | 排速度曲线：一快一慢一呼吸（`49` §二） |
| 台词顶到切点 | 说完最后一字就切下一段 | 留 0.6 秒余量，CT13 会告警 |
| 动作缺预备/跟随 | 人突然弹起来、停在半空姿势 | 补三拍，重写这一段（`52` 一） |

## 8. 典型调用

**例 1**：用户发来剧本＋分镜＋「按关键词技能做《X》第 3 集」
→ 读设定 → ingest 对齐 → 切组账目 → 总览表确认 → 样张 → 批量 → 自检 → 校验 → 交付。

**例 2**：用户只给分镜
→ 停，要剧本；说明「关键词脚本必须逐字还原台词，缺剧本会改剧情」。

**例 3**：用户说「继续第 4 集」
→ 读第 3 集 kwdata 与自检，接续空间/人物/编号，不重写已确认内容。

**例 4**：用户说「太慢了，直接全出」
→ 可以一次出多组，但仍必须先给总览表；账目对了再写，否则返工更慢。

**例 5**：用户要改某一句台词
→ 改 `kwdata.json` 里对应 shot，重跑 build；**不许直接改 Excel**。
