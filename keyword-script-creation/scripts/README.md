## 技法层规则（CT 规则码）

校验器在原有规则之外，追加 **CT00–CT15** 技法层与写法层规则，实现见 `ct_rules.py`（与另一技能同名文件内容一致，改完必须同步两份）。

| 规则码 | 级别 | 触发条件 | 处理 |
|---|---|---|---|
| CT00 | warning | `cine_tech.json` 未部署或条数 ≠ 300 | 重跑 A1 部署；技法层降级为纯文本规则，但不许静默 |
| CT01 | error | 出现空泛词（电影感/氛围感/大片感/油画感/二次元/唯美/震撼/情绪张力…） | 换成可观察或可测量写法（45 §3） |
| CT02 | error | 关键词层 `params` 九子参数缺项或乱序 | 补齐定序：摄影机→质感→色彩→机位→运镜→光影→动作→场面调度→参考电影 |
| CT03 | warning | 同一镜出现 ≥2 个运动轴（同族算一轴，手持不算轴） | 一镜一主运镜，辅技法降级（45 §5.1） |
| CT04 | — | 单镜时长上限 | 由各 `verify.py` 自身检查，`ct_rules.py` 不重复 |
| CT05 | error | 正文出现《片名》典故 | 移入「画面参数·参考电影」 |
| CT06 | error | 参考电影 >1 部或非《片名》年份格式 | 限 1 部，补年份 |
| CT07 | error | 正文出现英文技法名（词表由 `cine_tech.json` 的 `en` 字段现生成，295 条） | 降维成中文可执行写法（45 §1 / 45 §2） |
| CT08 | error | 出现 T4 禁投技法中文名（一镜到底/叠化/长镜/分屏/绿幕…共 32 条） | 改用 45 §5 等价替代写法（或 95 §八 查档位）；前置「无/禁/不/非/免」的否定写法不算命中 |
| CT09 | error / warning | 运镜无运动轴且未写「固定」（error)；有轴但无量化（米/度/秒，warning）。推镜头／拉镜头／移镜头／跟镜头 这类省略写法也算轴 | 写入 41-运镜库 的主运镜＋四要素：「推近 0.3 米，用时 2 秒」 |
| CT10 | error / warning | 光影缺色温 K 或光比 1:n（error）；缺光位或光质（warning） | 按 42-打光库 四件套补齐：光位＋光质＋色温＋光比 |
| CT11 | error / warning | 钩子写法（黑场/倒放/静默/炸光/先声后影/结果前置）落进运镜字段（error）；**首组 0—2 秒**（按 `shots[].dur` 累加到 2.0 秒，含跨过 2 秒那一镜）里没有钩子特征词（warning） | 钩子写进首镜的画面主体/动作/音效（48 §6）；每组前 2 秒必须有异常。只看首组首段，不做全片扫描——全片扫等于「片里任意角落出现一个『撞』字就过」，太松。认两类词：12 条模板名＋冲撞/伤害类事件词（撞/摔/砸/耳光/血…）。旧片实测（82 份历史交付，无 `dur` 字段，探针按分镜序号近似切首段）告警 67.1%：旧交付多数确实用「特写液滴/晨雾全景」慢开场，这是规则想拦的东西，不是误报。分镜技能共用同一份实现，只是把首组换成首单元、dur 换成 duration（_head_text 两个字段都认），口径一致 |
| CT12 | error | 出现英制单位（ft/feet/inch/mph/yd） | 换成米/厘米（1ft≈0.3 米），参数一律公制 |
| CT13 | warning | 台词说完到这一组结束不足 0.6 秒（按组算，不按镜算：一组一次生成、一个切点，台词常跨镜说完） | 拆组、挪台词或延时长，不许加快语速（49 §三） |
| CT14 | warning | 一集 `movement` 的运动轴种类 <4（组数 ≥5 才查，扫全部 `shots[].cam`） | 从 41-运镜库 换轴，并留一个招牌镜（49 §五） |
| CT15 | warning | 相邻 3 个组（分镜层是单元）时长完全一样 → 一个速度走到底 | 排速度曲线：一快一慢一呼吸（49 §二） |

CT07 只扫镜头文本（cam、pic、style）；`params` 里的英文参数（ARRI、f/2.8、roll）不参与英文名判定，但参与 T4 中文名判定（CT08）。

## 跨表校验（X 规则码）

分镜表与关键词表各自合法、合起来错位，是这条流水线最容易漏的一类返工：分镜写了 44 镜、关键词只写了 41 镜，两边的时长账目各算各的，交付时才发现第 5 集少生成了三个镜头。`crosscheck.py` 专门查这一层。

```powershell
python scripts/crosscheck.py --storyboard 分镜.json --keyword work/S03_kwdata.json
```

`--storyboard` 吃两种输入：分镜技能 `ingest.py` 产出的 source JSON（`storyboard.rows`），或分镜格式的 `units[]`。两级技能目录下各有一份 `crosscheck.py`，内容一致。

| 规则码 | 级别 | 触发条件 | 处理 |
|---|---|---|---|
| X01 | error / warning | 关键词组挂的单元在分镜里不存在（error）；某个分镜单元还没写关键词组（warning） | 核对单元名（U1 / U01 / u1 都认数字）；整单元漏写就补写 |
| X02 | error | 某单元分镜 N 镜、关键词只写了 M 镜（N>M） | 漏镜＝少生成一个镜头，补齐 |
| X03 | error | 关键词写多了分镜没有的镜（M>N） | 多镜＝凭空加一段，删掉或回分镜补 |
| X04 | warning | 同一镜时长差 >0.05 秒 | 两边的账目改成同一个数 |
| X05 | warning | 同一镜景别不一致（MCU / 中近景 会归一化后再比） | 定一个，另一层跟着改 |
| X06 | warning | 单元台词字数差 >20%（只数 `dialogue` 与音频列的台词，环境音不算） | 台词不许删（红线），口语化压缩也要报备 |
| X07 | warning | 单元总时长与关键词组总时长差 >0.05 秒 | 拆组/合组时两边一起改 |

口径三条：**镜号按位置对，不按编号对**（关键词的镜号在每组内从 001 重新数，分镜的是全片连号）；**合组拆组都认**（一个单元拆成几组时，把组内镜头按序接起来比）；**台词按单元合计比，不按单镜硬对**（60 规定对白超过 3 秒要插反应镜，台词会挪到相邻镜）。

退出码：error 非空 → 1，只有 warning → 0。回归里已带一正一负两个夹具（`tests/cross/`、`tests/cross_bad/`）。

## 技法数据（cine_tech）

`cine_tech.json`（300 条）是 grokfilm 技法库的**只读副本**，真源在工作区 `技法库整合/`：

```powershell
Copy-Item 'F:\AI短剧\技法库整合\cine_tech.json' 'C:\Users\22718\.dsh\skills\<本技能>\...' -Force
```

校验器启动时会比对 `count == 300`，不一致只报警告、不阻断（避免误伤历史交付）。改数据改真源后重跑构建，勿手改副本。

## 技法映射表（可选）

镜头对象可带 `tech` 字段，`build_xlsx.py` 会按需生成「技法映射」表：

```json
"tech": "荷兰角｜C3c 画面参数·机位｜T2"
```

或对象形态 `{"name":"荷兰角","slot":"C3c 画面参数·机位","tier":"T2","params":"roll 12度"}`。
没有该字段时**不生成**该表，历史数据零影响。
