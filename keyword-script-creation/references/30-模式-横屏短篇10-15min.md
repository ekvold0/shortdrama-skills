# 模式 · 横屏短篇视频 10–15 分钟

> 只写与 `00-总纲`、`20-模式-横屏4x3` 不同的部分。短篇规范为 V1.2。
> 一句话区别：短剧是「钩子—反转—钩子」，短篇是「建置—对抗—结局」的完整故事。

## 一、参数卡

| 项 | 值 |
|---|---|
| 画幅 | 4:3，1920×1440 |
| 模型 | 同横屏：2.0 为主，2.5 ≤30 秒并标注 |
| 单组时长 | 4–15 秒（2.5 ≤30） |
| 组内分镜 | 2–6 个 |
| 全片 | **600–900 秒（10–15 分钟）** |
| 序列组总量 | 按平均 8–12 秒/组，**约 55–110 组** |
| 编号 | `M幕-C场-XZ-序号`，如 `M1-C03-XZ-012`；XZ 全片连续 |
| 结构 | 三幕 ＋ 场次 ＋ 8 个叙事节点 |

## 二、三幕结构与比例

| 幕 | 占比 | 约合时长 | 任务 |
|---|---|---|---|
| 第一幕·建置 | 20%–25% | 2–3.5 分钟 | 建立人物、时空、基调、核心欲望；幕末用激励事件打破平衡 |
| 第二幕·对抗 | 50%–55% | 5–8 分钟 | 行动—障碍—升级；中点放重大转折/真相/关系反转；幕末跌入危机 |
| 第三幕·结局 | 20%–25% | 2–3.5 分钟 | 危机应对、高潮对决、解决；完成人物弧光，收束主题 |

比例是硬账：`verify.py` 会按各幕累计时长核算，偏差超过 ±5 个百分点报错。

## 三、场次与编号

1. **换场判定**：时间或地点任一变化即换场；同一场含若干连续序列组。
2. 场次编号 `C01` 起；序列组号 `XZ` 全片连续，不按场重置。
3. 闪回/梦境/平行时空作为特殊场次，在总览表标注，编号加【闪回】等。
4. 场次规划必须在写正文前完成，并与分镜脚本的场景边界对齐；不一致以剧本为准，回查分镜。

## 四、八个叙事节点（缺一不可）

开场钩子 → 激励事件 → 第一转折点 → 中点 → 第二转折点 → 危机 → 高潮 → 结局。

写进总览表「关键节点」列，并在第三次自检逐条核对：
- 激励事件是否在第一幕末？
- 中点是否有真相/反转，而不是又一次争吵？
- 第二转折点是否让主角失去最重要的东西？
- 高潮是否解决核心冲突（不是解决次要矛盾）？

## 五、开场与结尾

- **开场**：前 15–30 秒完成时空建立＋注意力吸引（建立镜头＋悬念/冲突/异常信息）。不要求短剧式黄金 3 秒强反转，但要迅速交代主角处境，不能冗长铺垫。
- **结尾**：完成高潮收束、人物弧光落点或主题表达；可留余味或开放悬念，但不能「没说完就黑屏」。

## 六、节奏曲线与人物弧光

- 曲线：舒缓建置 → 升级对抗 → 高潮释放 → 情绪收束；强冲突段与抒情段交替，避免全程高压或长时间平铺。
- 允许为情绪沉淀、环境氛围、人物关系留白设置舒缓长镜头——但每镜必须承载信息或情绪功能。
- 人物弧光：主要人物的情绪/关系/认知变化贯穿三幕；各组情绪物理化服务于弧光走向，前后变化要可信。

## 七、账目纪律（短篇最关键）

1. **先出总览表再写正文**：逐组登记 幕/场/编号/场景/时长/模型/核心事件/累计时长。
2. 写正文前算一遍：总时长是否在 600–900 秒；各幕占比是否达标；组数是否在 55–110。
3. **每写完一场回填实际时长**，随时看得见「还差多少秒」。
4. 超时/不足只能通过「合并或拆分序列组、调整场次内容」解决；**严禁加快语速、拖慢台词、堆空镜硬凑**。
5. 终稿账目必须闭合：各组时长之和 = 全片总时长；总览表累计 = 正文逐组合计。

## 八、短篇专属自检（并入 `90` 第三次循环）

- [ ] 三幕完整，占比在 20-25 / 50-55 / 20-25 区间
- [ ] 八个节点齐备，位置合理
- [ ] 全片总时长 600–900 秒，组数 55–110
- [ ] 人物弧光有起点、转折、落点
- [ ] 节奏张弛有度，无全程高压/长时间平铺
- [ ] 总览表与正文逐组一致（编号/时长/模型/核心事件）

## 九、短篇高频错误

| 错误 | 症状 | 改法 |
|---|---|---|
| 拍成加长短剧 | 每 30 秒一个反转，人物没立住 | 回到三幕，先建置再升级 |
| 中点无转折 | 第二幕只是吵架升级 | 中点放真相/关系反转 |
| 高潮解决次要矛盾 | 打完架核心问题还在 | 高潮对准核心冲突 |
| 硬凑时长 | 空镜、慢动作、重复台词 | 补事件或拆组，不注水 |
| 场次混乱 | 同一地点被拆成三场 | 按「时间/地点变化」重划 |
| 总览表不更新 | 正文与账目对不上 | 每场写完立即回填 |

## 十、分批交付

短篇 55–110 组，一次输出必被截断。**按场分批**（每场 5–8 组），每批写完落盘 JSON，下一批从断点续。每批交付时报：本场组数、本场时长、全片累计、距目标还差多少。
