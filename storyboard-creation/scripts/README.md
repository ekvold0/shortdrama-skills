# scripts 使用说明

两个脚本都不依赖第三方库以外的包：`verify.py` 只用标准库，`build_xlsx.py` 用 `openpyxl`（DSH 运行时自带）。

## 一、数据格式（storyboard.json）

一个 **单元（unit）＝ 一个 AI 生成块**，单元内可含多个镜头（shots）。单元级字段就是交付文本的 14 个字段。

```json
{
  "meta": {
    "project": "剧名",
    "episode": "S01",
    "mode": "vertical | horizontal | shortfilm",
    "aspect": "9:16",
    "resolution": "1080x1920",
    "target_seconds": 180,
    "total_seconds": 174.5,
    "check_date": "2026-10-26",
    "anchors": [{"type": "角色", "name": "A", "content": "……"}],
    "line_changes": [{"shot": "S01-003", "original": "……", "rewritten": "……", "reason": "……"}]
  },
  "units": [
    {
      "id": "U01",
      "scene": "S01",
      "coord": "M1-S01 / 单元 U01（功能）",
      "shot_id": "S01-001",
      "source": "原文片段",
      "aspect": "9:16｜1080×1920",
      "style": "视觉风格",
      "cast": "出场角色与主体",
      "time": "深夜",
      "era": "当代",
      "date": "冬季·老街面馆",
      "weather": "约 2 度，无风",
      "timeline": "第 0.0–3.0 秒｜……",
      "action": "动作拆解",
      "emotion": "情绪拆解（标 A/B/C）",
      "emotion_level": "C",
      "line": "",
      "sound": {"voice": "无", "fx": "……", "ambience": "……", "reverb": "……"},
      "link": "衔接备注",
      "shots": [
        {"id": "S01-001", "size": "MS", "duration": 3.0, "camera": "……", "content": "……"}
      ]
    }
  ]
}
```

要点：
- `shots[].duration` 的单位是秒，可用小数；`meta.total_seconds` 是声明总时长，必须等于各单元之和。
- `emotion_level` 只能是 `A` / `B` / `C`。
- `sound` 四个键必须齐（没有内容写 `"无"`）。
- `line` 可以是字符串，也可以是 `[{"role","text","start","end"}]`。

## 二、校验

```bash
python verify.py storyboard.json
python verify.py storyboard.json --json report.json
```

检查项：
1. 单元字段齐全、镜头字段齐全、景别在枚举内
2. 单元 4–15 秒、单镜不超模式上限（竖屏 8 / 横屏 10 / 短篇 15）
3. 各单元合计 ＝ 声明总时长（误差 0.05 秒）；不超 target
4. 镜号唯一且在场景内连续
5. 违禁表述：同上/同前、牛顿/毫米/频率/赫兹、肌群名、BGM/配乐、叠化/淡入、裸左右方位、半角度
6. 台词语速：单元台词字数 ÷ 单元时长 ≤ 3.5 字/秒；< 1.5 提醒是否留白过多
7. 声音四层是否齐
8. 情绪分级合法性；B 级 0 次或 >3 次提醒
9. `meta.aspect` 缺失直接判失败（画幅不得假设）

退出码 0 = 通过（可能有警告），1 = 有失败项。

## 补充说明（试跑后新增）

- 台词语速按 `line` 里每句的 `start/end` 核算；没有起止时间才退回单元总时长。
- 计字数时会自动剔除【旁白】【闪回】这类方括号标记，不会把标记算成语速。
- `line: []` 表示本单元无对白，**不报警告**；只有字段缺失才报。
- 情绪分级：B 级 0 次或 >3 次都会提醒。B 级只该给真正的转折与峰值，其余写 `C 级（强度高，不计为峰值）`。
- 画幅（`meta.aspect`）缺失直接判失败——画幅必须由用户提供。

## 三、生成 Excel

```bash
python build_xlsx.py storyboard.json -o 交付.xlsx
```

五个工作表：

| Sheet | 内容 |
|---|---|
| 分镜表 | 七字段表格，自动换行、列宽、冻结表头、筛选 |
| AI单元 | 每单元 16 行（字段 / 内容），方便直接复制 |
| 锚点表 | 角色、声线、道具、视觉、空间；未填时给占位行 |
| 自检 | 项目信息 + 39 项三轮自检（留空待填） |
| 台词留痕 | 原句 / 改写句 / 理由 |

## 四、推荐流程

```bash
# 1. 写完一批单元后先校验
python verify.py s01.json
# 2. 修完失败项再生成交付件
python build_xlsx.py s01.json -o 归途_S01_分镜_v1.xlsx
```

样例：`example_storyboard.json`（2 单元 4 镜，可跑通）。

## 技法层规则（CT 规则码）

校验器在原有规则之外，追加 **CT00–CT15** 技法层与写法层规则，实现见 `ct_rules.py`（与另一技能同名文件内容一致）。

| 规则码 | 级别 | 触发条件 | 处理 |
|---|---|---|---|
| CT00 | warning | `cine_tech.json` 未部署或条数 ≠ 300 | 重跑 A1 部署；技法层降级为纯文本规则，但不许静默 |
| CT01 | error | 出现空泛词（电影感/氛围感/大片感/油画感/二次元/唯美/震撼/情绪张力…） | 换成可观察或可测量写法（45 §3） |
| CT02 | error | 关键词层 `params` 九子参数缺项或乱序 | 补齐定序：摄影机→质感→色彩→机位→运镜→光影→动作→场面调度→参考电影 |
| CT03 | warning | 同一镜出现 ≥2 个运动轴（同族算一轴，手持不算轴） | 一镜一主运镜，辅技法降级（45 §5.1） |
| CT04 | — | 单镜时长上限 | 由各 `verify.py` 自身检查，`ct_rules.py` 不重复 |
| CT05 | error | 正文出现《片名》典故 | 移入「画面参数·参考电影」 |
| CT06 | error | 参考电影 >1 部或非《片名》年份格式 | 限 1 部，补年份 |
| CT07 | error | 正文出现英文技法名（词表由 `cine_tech.json` 的 `en` 字段现生成，295 条） | 降维成中文可执行写法（55 §1 / 45 §2） |
| CT08 | error | 出现 T4 禁投技法中文名（一镜到底/叠化/长镜/分屏/绿幕…共 32 条） | 改用 55 §7 等价替代；前置「无/禁/不/非/免」的否定写法不算命中 |
| CT09 | error/warning | 关键词层 `movement` 既无运动轴也没写「固定」→ error；有轴但没写米/度/秒 → warning | 分镜层不查（禁量化），只在写关键词时补四要素（43 §1、关键词 41） |
| CT10 | error/warning | 关键词层 `light` 缺色温 K 或光比 1:n → error；缺光位或光质 → warning | 按关键词 42 的四件套补；分镜层只写光位/光质/冷暖，不写数（44 §1） |
| CT11 | error/warning | 钩子写法（黑场/倒放/静默/炸光…）出现在 `movement` 或机位列 → error/warning；**分镜层**首单元 0–2 秒、**关键词层**首组 0–2 秒内找不到任何钩子特征词 → warning | 钩子写进画面内容，首镜压到 ≤2 秒（46、关键词 48） |
| CT12 | error | 参数里出现英制单位（ft / feet / inch / mph / yd） | 换成米/厘米（1ft≈0.3 米） |
| CT13 | warning | 关键词层：台词说完到这一组结束不足 0.6 秒（按组算，不按镜算） | 拆组、挪台词或延时长，不许加快语速（关键词 49 §三） |
| CT14 | warning | 关键词层：一集 `movement` 的运动轴种类 <4（组数 ≥5 才查） | 换轴并留一个招牌镜（关键词 49 §五）；分镜层靠 48 与人工 |
| CT15 | warning | 相邻 3 个单元（关键词层是组）时长完全一样 → 一个速度走到底 | 排速度曲线：一快一慢一呼吸（48 §二） |

CT07 只扫镜头文本（机位、画面内容、style）；关键词层 `params` 里的英文参数（ARRI、f/2.8、roll）不参与英文名判定，但参与 T4 中文名判定（CT08）。

**CT09/CT10 只查关键词层**——分镜层按「数值分层」禁量化（55 §8），写了 K 值和光比反而会被判越层，靠 `70-自检清单` 第三轮附 3G/3J 人工拦。CT11 两层口径不同但共用一份词表：分镜层读 `units[0]` 的 `duration` 累加，关键词层读 `groups[0]` 的 `dur` 累加（`_head_text` 两个字段都认）。

## 技法数据（cine_tech）

`cine_tech.json`（300 条）是 grokfilm 技法库的**只读副本**，真源在工作区 `技法库整合/`：

```powershell
Copy-Item 'F:\AI短剧\技法库整合\cine_tech.json' 'C:\Users\22718\.dsh\skills\<本技能>\...' -Force
```

校验器启动时会比对 `count == 300`，不一致只报警告、不阻断（避免误伤历史交付）。改数据改真源后重跑构建，勿手改副本。

## 技法映射表（可选）

镜头对象可带 `tech` 字段，`build_xlsx.py` 会按需生成「技法映射」表：

```json
"tech": "荷兰角｜C3c 画面参数·机位｜T2"
```

或对象形态 `{"name":"荷兰角","slot":"C3c 画面参数·机位","tier":"T2","params":"roll 12度"}`。
没有该字段时**不生成**该表，历史数据零影响。
