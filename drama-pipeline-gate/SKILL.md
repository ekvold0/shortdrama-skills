# 短剧生成链：验收闸门（跨项目通用）

这套规则解决一件事：**写下去的东西，有没有按写的那样被生成出来。**
它只管“剧本 → 分镜 → 关键词 → 素材”这条链的确定性；成片质量、剪辑节奏、观众观感不在范围内。

## 何时生效

任何“文档 → AI 视频素材”的交付任务：分镜头脚本、关键词脚本、序列组提示词、素材验收、提示词体检、成片前核对。不限于某一个项目。

## 第一件事：找尺子（30 秒）

1. 定位项目根（当前工作目录向上找，或问用户）。
2. 找项目里的 `流程/gate.py`、`流程/anchors.py`、`流程/README.md`。
3. **有** → 直接用。
   **没有** → 从本技能的 `scripts/gate.py`、`scripts/anchors.py` 复制到新项目的 `流程/` 下，跑一次确认可用，再动手做内容。
4. 项目自有口径（语速、画幅、时长）优先于本技能默认值；冲突时问用户，不要自己选。

## 三条不变量（违反任意一条，任务视为未完成）

1. **单一真值源**：人物外貌只在 `anchors.py` 写一次，各集文档逐字复刻，禁止手改单集。
2. **硬门禁**：交付前必跑闸门，红灯 ≠ 0 不许交付，不许“先交付后补跑”。
3. **外部验收**：只证明“文档自洽”不算通过，必须有生成物回读或人评记录。

## 交付前必跑

**关键词脚本 / 分镜：**

```
python 流程/gate.py lint    "<关键词脚本.xlsx>"
python 流程/gate.py anchors "<关键词脚本.xlsx>"
```

**素材（生成后）：**

```
python 流程/gate.py assets "<素材目录>" "<关键词脚本.xlsx>"
```

**投喂核对（画布分享链接）：**

```
python 流程/gate.py readback "<分享链接>" --out x.json
```

## 阈值（默认值，项目可覆盖）

| 项 | 阈值 |
|---|---|
| 画幅·生成门槛 | 720×1280（9:16） |
| 画幅·交付门槛 | 1080×1920，由后期超分承担 |
| 组时长 | 4—15 秒 |
| 语速 | 2.0—3.5 字/秒 |
| 文字 | 零容忍：画面内不生成文字、字幕、水印、日期 |
| 时长偏差 | 单组 ±0.5 秒，全集 ±2% |
| 锚点 | 逐字一致，0 偏差 |

## 交付说明必须包含

1. 闸门原始输出（几组、几红几黄）。
2. 黄灯逐条转人评的结论。
3. 明确列出“本次未验证的项”。
4. 用了项目覆盖值的，写明覆盖理由。

## 已知边界（别重复踩）

- **禁止词管不住联想**：“无任何标识”仍会画出徽章。要用正面描述占满画面（“左胸一整片素净布面、无缝线、无贴布”），反向词用中文具体词（徽章、臂章、胸标、绣花标），**不要用 logo 这个词**。
- **精确计数不可靠**：“三个空座”“两个人”必须人评抽帧确认。
- **镜头数按实测设计，不按理想镜数写**：先看同类项目实测——竖屏 11—12 秒通常只出 3 镜；若模型持续压镜，就按实际能力设计镜头单元，一镜到底优先于多镜拼贴。
- **ffmpeg 场景切点在竖屏素材上严重过检**（实测 28 个切点 vs 设计 5 镜），不能作镜数判据。
- **闸门只证明文档自洽，不证明画面正确**，两者必须分开汇报，不许混为一谈。

## 升级与改判

- 项目还没有验收协议 → **先花 10 分钟写最小协议**（检查项 + 阈值 + 退出码），再动手做内容；不要“先做后验”。
- 任何结论性文档（判决书、复盘、方法论总结）必须包含**改判触发线**：什么情况出现时这个结论作废。

## 不要做的事

- 不要为了让闸门变绿而放宽阈值或加豁免；要改阈值必须说明理由并留痕。
- 不要用“基本符合”“大体一致”“差不多”替代数字。
- 不要把“自检通过”当成“验收通过”——前者是文档内部一致性，后者是生成物回读。
