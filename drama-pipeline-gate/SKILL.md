# 短剧生成链：验收闸门（跨项目通用）

> 版本：**V2.12**｜更新：2026-11-26
> 编号说明：本技能历史上用自己的 `v1.0 → v2.2` 序列，为与两个内容技能对齐，自本版起统一用 **V2.12**；旧编号对应关系 v2.2 = 分镜/keyword 的 V2.12 同批。
> 本版新增：角色锚点两阶段（`references/角色锚点两阶段_v1.md`）、流程单页（`references/短剧生成流程_v1.md`）、外部验收核对表、改判记录、`run_generate.py` dry-run、并行生成、成品落库口径。

这套规则解决一件事：**写下去的东西，有没有按写的那样被生成出来。**
它只管“剧本 → 分镜 → 关键词 → 素材”这条链的确定性；成片质量、剪辑节奏、观众观感不在范围内。

## 何时生效

任何“文档 → AI 视频素材”的交付任务：分镜头脚本、关键词脚本、序列组提示词、素材验收、提示词体检、成片前核对。不限于某一个项目。

## 第一件事：找尺子（30 秒）

0. **先读流程单页**：`references/短剧生成流程_v1.md`——六阶段五闸门的全景，说明每个阶段该交出什么、闸门卡在哪、为什么分镜图必须夹在"资产统一之后、视频之前"。这份是本技能的总图，别跳过直接去跑 lint。
1. 定位项目根（当前工作目录向上找，或问用户）。
2. 找 `流程/gate.py`、`流程/anchors.py`、`流程/角色锚点.json`、`流程/README.md`。
3. **有** → 直接用。
   **没有** → 从本技能的 `scripts\` 复制 `gate.py`、`anchors.py` 到新项目 `流程/` 下，跑一次 `gate.py lint` 确认可用，再动手做内容。
4. **新剧第一件事：登记角色名**（不要先去改代码）。`python 流程/anchors.py init --script <剧本.docx> --out 流程/角色锚点.json` 从剧本人物表抽名字，人工删掉路人、合并同名写法；等外貌/服装定了再补 `anchor` 与 `features`，把 `stage` 从 `names` 升到 `look`/`full`。规范见 `references/角色锚点两阶段_v1.md`。
   角色表还是内置示例（林晓/王桂兰/老周/陈姐）时，`gate.py anchors` 会**明确报红并 exit 1**——不再静默空跑。
5. 项目自有口径（语速、画幅、时长）优先于本技能默认值；冲突时问用户，不要自己选。

## 三条不变量（违反任意一条，任务视为未完成）

1. **单一真值源**：人物外貌只在 `流程/角色锚点.json` 写一次（`stage=full` 才算写完），各集文档逐字复刻，禁止手改单集。
2. **硬门禁**：交付前必跑闸门，红灯 ≠ 0 不许交付，不许“先交付后补跑”。
3. **外部验收**：只证明“文档自洽”不算通过，必须有生成物回读或人评记录。

## 两条补充不变量（V2.0 图像资产层）

4. **参考链分双链**：身份链（长相／发型／服装）只引原始大脸卡，**禁止代际传递**；空间链（站位／墙／家具）允许逐段传记录帧，但必须同时挂原始无人场景图作依据。任何"卡生卡再传卡"都是串脸的开始。
5. **图先于字**：无人场景图 → 色卡（取 HEX）→ 角色卡三类 → 站位线稿 → 分镜图 → 才写关键词。图没齐就写提示词，等于拿文字去猜图。

素材上限（写 `[图片N]` 前必须算）：Seedance 2.0 系列 **9 图/3 视频/3 音频**（音频不可单独用；本组生成 4–15 秒；单条参考视频/音频 4–15 秒；视频组与音频组各 ≤15 秒）；2.5 flash **10/5/5**（本组生成 4–30 秒；单条参考视频/音频 4–30 秒；组总时长各 ≤30 秒）；2.5 标准版 **30/10/10**（本组生成 4–30 秒；支持纯音频参考；单条参考 4–30 秒；组总时长各 ≤30 秒）。**三档的组时长下限一律 4 秒**，没有哪个档位能生成 2–3 秒的组。放不下就是该拆组。

## 交付前必跑

> 四个命令跑完还不算交付：再填 `references/外部验收核对表_v1.md`（GT-02）逐项打勾。闸门绿 = 文档自洽，勾完 = 画面对得上，两件事分开汇报。

**关键词脚本 / 分镜：**

```
python 流程/gate.py lint    "<关键词脚本.xlsx>"
python 流程/gate.py anchors "<关键词脚本.xlsx>"
```

**素材（生成后）：**

```
python 流程/gate.py assets "<素材目录>" "<关键词脚本.xlsx>"
```

**生成前（FL-06，投喂清单）：**

```
python scripts/run_generate.py "<关键词 kwdata.json>" --assets "<素材根>" [--limit N]
```

dry-run，不联网不花钱：逐组核 `[图片N]`↔refs 是否对齐、图/视频/音频有没有超档位上限、音频有没有单独用、素材文件在不在，再算总预算、排产物文件名，出 `投喂清单_<剧名>_S<集>.md/.json`。有阻塞项 `exit 1`；`--live`（真发单）尚未实现，会 `exit 2` 并列出待确认项。

它现在能回读三件事，不再只看分辨率：

| 回读项 | 判定 | 说明 |
|---|---|---|
| 时长偏差 | FAIL（>±0.5 秒） | 老口径 |
| 画幅 | FAIL | 竖屏 1080×1920 / 720×1280；横屏 16:9 1920×1080 / 1280×720；横屏 4:3 1440×1080 / 960×720 |
| **黑帧/空白帧** | **FAIL** | `blackdetect`，≥0.08 秒就算；转场空白帧是明确失败项 |
| **镜数与镜长** | 待核（不 FAIL） | 切镜算出来的镜子数 vs 脚本「微观分镜」数；AI 生成运动会持续触发切点，绝对值不能当验收依据，但「脚本 4 镜、实测 12 镜」值得人看一眼 |

切镜引擎有两条：装了 `pip install scenedetect opencv-python-headless` 就用 PySceneDetect 的 ContentDetector（最准，按 HSV 加权）；没装就退回 ffmpeg 的场景分数——但只用场景分数会漏掉底色相近的切点（红#FF0000→绿#00FF00 的灰度差只有 0.29，低于 0.35 的阈值，实测把 4 段素材切成 3 镜），所以 ffmpeg 这条现在**同时跑两套分并取并集**：`select=gt(scene,…)` 的灰度分 + `scale=16:16,format=rgb24` 抓帧算的 RGB 平均绝对差（阈值 0.20）。此外所有碎镜（<0.2 秒）一律并进前一镜，避免片尾出现 0.06 秒的假镜。报告里的「切镜引擎」字段写明这次走的是哪条。

- **镜数按「至少几镜」判（V2.3）**：>= 计划数不提示（AI 生成的运动与浅景深会持续触发切点，5 镜的设计切出 8–12 段是常态）；**少于计划数**才标「镜数待核」，超过 3 倍也标（读数不可信）。镜数永远不进 FAIL，只提示人看一眼。
改过阈值或升级过依赖，跑一遍自检：

```
python scripts/selftest.py          # 在技能目录里跑：现造 4 段假素材，验切镜/黑帧/账目
```

`selftest.py` 会自己用 ffmpeg 生成测试视频，不需要任何真实素材；没 ffmpeg 时返回 2（什么都没验，不算通过）。

**投喂核对（画布分享链接）：**

```
python 流程/gate.py readback "<分享链接>" --out x.json
```

**落库口径（V2.10）：**

- 文件 `<剧名>_<组号>_v<版本>.mp4`，画布节点标题 `<组号>`（补帧 `_补帧`）——`gate.py assets` 按节点标题认组。
- 版本号由 `run_generate.py` 自动递增：扫输出目录取最大 `_v{n}`，`meta.version` 小于等于它就 +1 并提示；旧版移到 `archive/`，不覆盖。
- 组号正则缺省 `S\d+-XZ-\d+`；换编号体系用环境变量 `GATE_GROUP_PATTERN` 覆盖；认不出组时 `gate.py assets` 打红字。

## 阈值（默认值，项目可覆盖）

| 项 | 阈值 |
|---|---|
| 画幅·生成门槛 | 竖屏 720×1280（9:16）／横屏 16:9 1280×720／横屏 4:3 960×720 |
| 画幅·交付门槛 | 竖屏 1080×1920／横屏 16:9 1920×1080／横屏 4:3 1440×1080，由后期超分承担 |
| 组时长 | 4—15 秒 |
| 排时长基准 | 2.25 字/秒（`SPEECH_CPS`，用来把台词字数换成秒数）|
| 台词语速上限 | 3.5 字/秒（`CPS_LIMIT`，超了就是红；真人念不了这么快）|
| 文字 | 零容忍：画面内不生成文字、字幕、水印、日期 |
| 时长偏差 | 单组 ±0.5 秒，全集 ±2% |
| 锚点 | 逐字一致，0 偏差 |

## 交付说明必须包含

1. 闸门原始输出（几组、几红几黄）。
2. 黄灯逐条转人评的结论。
3. 明确列出“本次未验证的项”。
4. 用了项目覆盖值的，写明覆盖理由。

## 已知边界（别重复踩）

- **禁止词管不住联想**：“无任何标识”仍会画出徽章。要用正面描述占满画面（“左胸一整片素净布面、无缝线、无贴布”），反向词用中文具体词（徽章、臂章、胸标、绣花标），**不要用 logo 这个词**。
- **精确计数不可靠**：“三个空座”“两个人”必须人评抽帧确认。
- **镜头数按实测设计，不按理想镜数写**：先看同类项目实测——竖屏 11—12 秒通常只出 3 镜；若模型持续压镜，就按实际能力设计镜头单元，一镜到底优先于多镜拼贴。
- **ffmpeg 场景切点在竖屏素材上严重过检**（实测 28 个切点 vs 设计 5 镜），不能作镜数判据。
- **闸门只证明文档自洽，不证明画面正确**，两者必须分开汇报，不许混为一谈。

## 升级与改判

- 项目还没有验收协议 → **先花 10 分钟写最小协议**（检查项 + 阈值 + 退出码），再动手做内容；不要“先做后验”。
- 任何结论性文档（判决书、复盘、方法论总结）必须包含**改判触发线**：什么情况出现时这个结论作废。

### 三条改判触发线（判定口径）

触发线不是“感觉不对就重来”，是三个有判据的开关。任一成立，按该条「触发后必须做」执行；记录一律追加到 `references/改判记录_v1.md`（表头见该文件首页）。

| # | 触发线 | 谁触发 |
|---|---|---|
| ① | 模型版本更新，且实测一致性 / 单条镜头数能力变化 | 执行人（平台版本号变了）／`gate.py assets`（镜数差、黑帧连续 3 批偏移）／抽检人（同一提示词脸型漂移） |
| ② | 参考链、衰减等实测结论与本文档假设冲突 | 抽检人、复盘人／`gate.py anchors`（旧措辞残留）或 CT23（参考链 > 1 代）报错 |
| ③ | 平台规则、画幅、时长或素材上限调整 | 平台公告、官方文档（执行人核对并附链接与生效日）／用户改口径 |

#### ① 模型能力变化

- **怎么测（唯一口径）**：固定同一批提示词 **3 条**——1 人近景、2 人对坐、走位全景各 1 条；同档位、同画幅、同长度，各跑 1 条。与旧结论逐条对照“脸型 / 服装 / 站位 / 镜数”，记差异条数。
- **判定**：3 条里 **≥2 条**出现差异 → 成立。只 1 条有差先按随机波动处理，加跑 1 条复测。
- **触发后必须做**：重估 ①本文档「已知边界」的镜头数条目 ②`短剧生成流程_v1.md` 第六节“模型压镜时的镜头数上限”“多图参考的实际成功率” ③受影响档位的并行批次上限（单条均价 `c` 变了，条数 `n` 跟着变）。
- **时限**：触发日起 **7 天**内落新结论；到期未测，旧结论自动标“待重估”，禁止再引用。
- **记录**：`改判记录_v1.md` 一行（触发线号 / 证据 / 旧→新 / 生效日）＋ 3 条对照产物路径。

#### ② 实测结论与假设冲突

- **判定**：要 **2 组同向反例**——同提示词，只改锚点代际（原始卡 vs 传递帧），其余不变，差异可指认（脸型、发际线、服装纹样任一处）。单次偶然串脸不触发，先复现。
- **触发后必须做**：重估 ①「两条补充不变量」第 4 条（参考链分双链）②流程「三、锚点闭环」的身份链／空间链表 ③「三·补 并行生成」的锚点纪律与批次表自检列。
- **时限**：反例落盘**即**作废旧口径；新口径 **7 天**内写进文档。期间禁止开新并行批次（已开的照旧验收，但不得跨批互引锚点）。
- **记录**：`改判记录_v1.md` 一行 ＋ 2 组对照帧路径（原始卡版 / 传递帧版）。

#### ③ 平台规则 / 画幅 / 时长 / 素材上限调整

- **判定**：官方文档或公告明示任一项变化即成立，**不需要实测**（单次素材上限、单条时长区间、组总时长、画幅、参考类型限制、能否纯音频）。
- **触发后必须做**：重估 ①「素材上限」段三档数字（9图+3视频+3音频 / 10-5-5 / 30-10-10）②「阈值」表 ③流程「四、素材上限」与第六节未验证项 ④`gate.py` 的 `GROUP_MIN`/`GROUP_MAX`、`RES_OK`、`CPS_LIMIT`——改代码必须跑 `scripts/selftest.py`，红灯 0 才算改完（本技能只写文档，改代码由执行人做）。
- **时限**：**公告生效日当天**改数或在该行标“待改”，同时停用受影响档位；不许一边用旧数字一边说“下版再说”。
- **记录**：`改判记录_v1.md` 一行 ＋ 公告链接与生效日 ＋ 改前／改后数字。

### 文档自身的版本与日期

`短剧生成流程_v1.md` 被改判时，按改动类型走两条路：

| 改动类型 | 文件名 | 版本号 | 日期 | 同步动作 |
|---|---|---|---|---|
| 补节、改判定口径、改一处阈值数字（P 阶段与闸门数量不变） | 原名不动 | 标题下版本行次版本 **+0.1**（v1.1 → v1.2） | 标题下 `> 版本：…｜更新：YYYY-MM-DD` 与文末「版本记录」表各加一行，两处同日 | 本文档版本行同步 +0.1；`改判记录_v1.md` 写旧→新 |
| 增删 P 阶段、增删闸门、改阶段顺序 | 新建 `短剧生成流程_v2.md`，旧文件首行加 `> 已被 v2 取代（YYYY-MM-DD），仅存档`，留在 `references/` | 主版本 **+1**（v2.0） | 旧文件头标注 + 新文件版本行 | 「第一件事：找尺子」第 0 步的引用改指新文件 |

- 日期用 `YYYY-MM-DD`，取改动落地那天，不取讨论那天。
- **禁止**只改内容不改版本行、只改版本不改日期、改完不记 `改判记录`——缺一即视为文档不完整，下一批交付不许引用该文档。
- 文件名里的 `_v1` 与版本行是两个东西：**只有主版本变化才改文件名**，次版本就地改。

## 不要做的事

- 不要为了让闸门变绿而放宽阈值或加豁免；要改阈值必须说明理由并留痕。
- 不要用“基本符合”“大体一致”“差不多”替代数字。
- 不要把“自检通过”当成“验收通过”——前者是文档内部一致性，后者是生成物回读。
