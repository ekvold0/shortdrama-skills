## 一、assets 回读：编号 / 文件 / 用途 三者一致

逐张回读，**一张一行**。三者指：资产登记表里的编号、磁盘上的实际文件、这个文件被挂到哪个单元的哪个 `[图片N]`。

| # | 资产编号 | 登记文件名 | 磁盘实际路径 | 用途（单元＋槽位） | 三者一致 | 缺陷类型 | 证据 |
|---|---|---|---|---|---|---|---|
| 1 | 角色卡-C01 | 大脸卡_C01.png | `20_资产/角色卡/大脸卡_C01.png` | S03-U03 ／ [图片1] | ☐ | 无 | |
| 2 | 场景图-S03 | 场景_S03.png | `20_资产/场景/场景_S03.png` | S03-U03 ／ [图片2] | ☐ | 无 | |
| 3 | 记录帧-REC_S02-U06 | REC_S02-U06.png | `40_生成/记录帧/REC_S02-U06.png` | S03-U03 ／ [图片3] | ☐ | 无 | |

缺陷类型（四选一，**逐条记，不许合并**）：

| 类型 | 定义 | 判据 |
|---|---|---|
| 缺图 | 登记表有编号、磁盘无文件 | 路径打不开／`ls` 里没有 |
| 错图 | 文件在，但不是该编号该出的内容 | 打开看图，与编号名不符（如 S03 场景出成 S05 的墙） |
| 张冠李戴 | 编号与文件都对，但被挂到了错误的单元或槽位 | 用途列写的是 A 单元，实际喂进了 B 单元 |
| 无 | 三者全对 | — |

登记口径：

- 视频成片的「存在/时长/黑帧/分辨率」**一律抄 `gate.py assets` 的 `summary` 与 `rows`**，不在本表重判（重判会出两套数字，交付说明对不上）。
- 图片资产（角色卡 / 场景图 / 道具卡 / 色卡 / 站位草图 / 分镜图 / 记录帧）`gate.py` **不扫**，本表是唯一回读入口。
- 取清单用一条命令，输出直接当证据贴进「证据」列：

```
Get-ChildItem "<资产目录>" -Recurse -File | Select-Object Name, Length, LastWriteTime
```

## 二、readback 投喂链接核对：链接指向的是不是同一份文件

`gate.py readback` 比的是**提交文本**（丢字段 / 特征词 / 文字风险 / 分辨率），**不比图片喂的是哪一版**。这一项没有工具兜底，必须逐条人核——防的就是"登记表是 v2、喂进去的是 v1"。

| 组号 | 槽位 | `[图片N]` | 投喂值（链接或文件 ID） | 登记表对应文件 | 比对依据（SHA256 前 8 位） | 一致 | 备注 |
|---|---|---|---|---|---|---|---|
| S03-U03 | [图片1] | 1 | `…/大脸卡_C01_v2.png` | `20_资产/角色卡/大脸卡_C01_v2.png` | `3f9a1c2b` ｜ `3f9a1c2b` | ☐ | |
| S03-U03 | [图片2] | 2 | `…/场景_S03_v1.png` | `20_资产/场景/场景_S03_v1.png` | | ☐ | |

规则：

| 项 | 判定 |
|---|---|
| 同一 `[图片N]` 对应两个文件 | 记一条"重复引用"，人评是否允许；默认不允许 |
| 同一文件被两个 `[图片N]` 引用 | 记一条"重复引用"，允许（同卡复用在闸门口径内） |
| 文件名带版本号（`_v1/_v2`） | 比对依据必须写哈希或"字节数＋尺寸"，**只比文件名不算核对** |
| 哈希取法 | `Get-FileHash "<文件>" -Algorithm SHA256 \| Select-Object -ExpandProperty Hash`（取前 8 位即可） |

> **镜数口径（V2.3）**：切镜读数按「至少几镜」判——实际 >= 计划即通过；少于计划才看一眼是否漏了节拍。镜数不进 FAIL，也不追求与设计逐镜对齐（AI 的运动、浅景深、光线变化都会持续触发切点）。

## 三、人评抽帧：精确计数不靠模型自述

必抽四类。`gate.py lint` 的 `计数需人评` 黄灯、以及任何"几个人/几个空座/手里拿的啥/什么颜色"的表述，全部落到这张表。

| 时间码 | 组号（单元） | 要数什么 | 判定口径 | 实测 | 结论 | 抽帧人-日期 |
|---|---|---|---|---|---|---|
| 00:03.20 | S03-U03 | 在场人数 | 可见完整躯干者计入；仅手臂/腿入画不计；镜面倒影不计 | 2 人 | ☐ | |
| 00:05.60 | S03-U03 | 空座数 | 只数场景图里存在的座位；被遮挡但可推断的标"存疑"单列 | 3 座（1 存疑） | ☐ | |
| 00:07.10 | S03-U03 | 手里道具编号 | 报编号（`道具卡-D02`），不写"一个杯子" | D02 | ☐ | |
| 00:09.40 | S03-U03 | 服装颜色 | 报色卡名或 HEX（`色卡-C03 深蓝 #1F3A5F`），不写"深色" | C03 | ☐ | |

规则：

- **不靠模型自述**：模型说"三个人"不算数，抽帧图上自己数。
- 抽帧落 `40_生成/抽帧/<组号>_<时间码>.png`，路径填进表（这就是证据）。
- 时间码取"人最全 / 道具最清楚"的那一帧；缺帧就说明这一条不可判，写 `未验` 并进交付说明「未验证项」。
- 结论只写 `✅` / `❌`；`❌` 时把"实测 vs 设计"的差写进备注，并在「本批结论」里走打回。

| 组号 | 设计镜数（脚本「微观分镜」计） | 实测镜数（`gate.py assets` 的 实际镜数） | 差（实测−设计） | 切镜引擎 | 压镜处置 | 说明 |

处置规则（照判，不靠感觉）：

| 差 | 处置 |
|---|---|
| ≤ +2 | 不改。人眼无跳切感即可 |
| ≥ +3 | 先人眼逐切点看。引擎是 `ffmpeg` 的过检不算（竖屏实测 28 切点 vs 设计 5 镜）；确认真跳切才处理 |
| 负值（实测 < 设计，压镜） | **优先改成一镜到底 + 运镜**，不往提示词里堆镜头描述，也不改时长账目去凑 |
