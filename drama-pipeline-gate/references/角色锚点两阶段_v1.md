# 角色锚点表 · 两阶段填写规范

> 所属：短剧生成流程 阶段一（资产）/ 闸门 GT-01 锚点单一源
> 配套：`scripts/anchors.py`（生成与自检）、`scripts/gate.py anchors`（逐组校验）、`scripts/gate.py readback`（特征词判红）
> 版本：v1.0｜2026-11-26

## 为什么要两阶段

剧本一到手就能确定的只有**名字**。外貌、服装、道具要等你看过剧本细节、定了风格、甚至图生图试过一轮才敢写死。

老做法把四个角色硬编码在 `anchors.py` 里，换一部剧不改文件，`anchors` 校验和 `readback` 特征词就会**静默空跑**——绿灯亮着，其实什么都没查。

新做法把角色表搬到一个 JSON 里，分两级填：

| 阶段 | 表里有什么 | 校验会做什么 | 什么时候进下一阶段 |
|---|---|---|---|
| ① 只登记名字（`stage=names`） | 名字、别名、身份 | 只查旧措辞残留 + 提示"这几个还没补" | 剧本读完、角色关系理清 |
| ② 补外貌（`stage=look`） | + `anchor`（可观察锚点句） | 开始查"定义型提及必须复刻锚点" | 定妆/风格确定后 |
| ③ 完整（`stage=full`） | + `features`（外形特征词） | readback 逐组判"提交文本有没有带上这些词" | 可以进关键词脚本 |

`stage` 不写会按内容推断：有 anchor 有 features → full；只有 anchor → look；都没有 → names。

## 第一步：先出名字

```bash
python anchors.py init --script "<项目根>/剧本/《剧名》/v4/第01集_xxx.docx" \
    --project "《剧名》" --out "<项目根>/《剧名》/角色锚点.json"
```

抽取优先级（越前越权威）：

1. 剧本自带的人物表 `人物：林晓、王桂兰、男乘客、乘客若干`（最可靠）
2. 行首台词标签 `林晓：…` / `【林晓】：…`（自动剥掉 `OS`/`VO`/`画外` 后缀）
3. `林晓说/林晓问` 这类叙述——**只给已出现的名字加权，不单独造名字**（否则"我就说"会把"我就"当成角色）

输出里每个名字带 `台词标签×N 提及×M` 证据数，方便你判断哪些是路人。

**生成的 JSON 要人工过一遍**：删掉不是角色的（"乘客若干""下一集"），把同一人的两个写法合并成 `aliases`。

## 第二步：补外貌

三种填法，按情况选：

**A. 有旧关键词脚本 → 直接回捞**

```bash
python anchors.py harvest --kw "<项目根>/关键词脚本/《剧名》/《剧名》01集关键词脚本.xlsx"
```

在「场景与妆造简述」里找 `角色名（…）` 的定义块，括号内容直接当 `anchor`，`stage` 设 `look`。存量剧集迁移用这个，一份都别手打。

**B. 从剧本细节推**（新剧）

按 `09-角色设计卡` 五块（身份/审美/脸/妆发/服装）写，只留**可观察、可测量**的：年龄、身高、脸型、发型、服装材质与磨损、配饰、姿态。不写"清纯""有气质"。

**C. 图生图试过后再定**

先按参考图出一版脸，定稿后把定稿特征写回 `anchor`——锚点句要能被下一个模型逐字复刻，不是给你自己看的备忘。

## 第三步：补 features（决定 readback 判不判红）

`features` 是 `gate.py readback` 的判据：关键词脚本里出现了这个角色，提交给即梦的文本就必须带上这些词，缺一个报红。

```json
{"name": "林晓", "features": ["深蓝", "工牌", "耳机"]}
```

挑词三原则：

1. 只挑**外形上不可省**的词（衣服主色、标志性配饰、发型/道具）
2. 别挑会换装的（一场婚礼就换一身，就报假红）
3. 2–4 个足够，宁少勿多

## 第四步：自检

```bash
python anchors.py check  角色锚点.json     # 表本身有没有矛盾
python anchors.py status 角色锚点.json     # 谁填到哪一级了
python anchors.py diff   角色锚点.json --script 剧本.docx   # 剧本人物表 ↔ 表，逐名对照
```

`check` 会抓的：

- 名字/别名重复挂了两个人
- `stage=look/full` 但 `anchor` 空或过短（<20 字）
- `stage=full` 但 `features` 空
- `stage=names` 但已经填了内容（忘了升级 stage）
- **两个角色的锚点完全相同**——同一个人的两个名字，该合并或设 `aliases`（真实案例：`男乘客` 与 `乘客` 锚点一模一样）

## 第五步：进闸门

```bash
set GATE_ANCHORS=<项目根>\《剧名》\角色锚点.json
python gate.py anchors  <项目根>\关键词脚本\《剧名》\《剧名》01集关键词脚本.xlsx
python gate.py readback <画布链接> <项目根>\关键词脚本\《剧名》
```

查找顺序：`GATE_ANCHORS` → 当前目录 `角色锚点.json` / `anchors.json` → 脚本同目录 → 都没有才退回内置示例四人（**此时会明确报红并 exit 1，不再静默放行**）。

## 两条口径

1. **比对先归一化**：顿号/逗号/括号写法不同不算错，"40岁上下男，中等身材" 与 "40岁上下，男，中等身材" 视为同一句。
2. **阶段一只查旧措辞**：名字登记了、锚点还没写，`anchors` 给黄灯不拦；但表还是内置示例时是红灯——那是"根本没登记"，性质不同。

## 已知限制

- 从自由文本里猜"未登记角色"不可靠（会把 `动作物理化拆解：` 这种段标当人名），所以这条检测**不进 gate**，改成确定性的 `anchors.py diff`（剧本人物表 vs 表）。
- `harvest` 只认 `名字（…）` 写法；写成 `名字：…` 的段落捞不到，会在输出里列出来。
- 一个人的锚点在「正向提示词」和「场景与妆造简述」里写成两个版本时，`anchors` 会报"未逐字复写"——这是要你统一口径，不是工具错。
